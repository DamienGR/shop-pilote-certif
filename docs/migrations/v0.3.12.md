# Socle v0.3.12

<!-- Ce que cette version demande à une boutique qui la prend. Lu par
     `shopctl core upgrade` et repris dans la pull request de mise à niveau. -->

Cette version ferme ce que la répétition de l'étape 8 de la certification
(jalon 10, `docs/certification/plan.md`) a trouvé, et livre le correctif de
`destroy` trouvé au passage réel de l'étape 7.

## Ce qui change

Outillage :

- **`deploy` nomme la bonne version pour revenir en arrière.** `rollbackTo`,
  dans le rapport, et la commande `wrangler rollback` proposée quand le test de
  fumée échoue, nommaient une version prise dans `wrangler versions list`, qui
  liste les dix dernières de la plus ancienne à la plus récente : sur le
  staging du pilote, chaque déploiement depuis l'étape 3 désignait la même,
  vieille de plusieurs semaines. `deploy` lit désormais la version qui sert
  **avant** de téléverser (`wrangler deployments status`) ; `null` quand il n'y
  en a pas ;
- **`restore` reverse les objets R2 dans les buckets de l'environnement
  restauré.** Il les écrivait sous les noms de buckets que l'archive porte,
  ceux de l'environnement où elle a été prise : une archive de staging
  restaurée en production remplissait le bucket de staging sur le même compte,
  et échouait sur un autre compte. Les objets suivent désormais leur liaison
  (`BUCKET`, `FILES`) ;
- **`restore` dit que le coffre ne voyage pas.** Les clés des fournisseurs sont
  chiffrées avec la `SECRETS_KEK` du Worker qui les a écrites : restaurées dans
  un autre environnement ou un autre compte, elles sont présentes et
  illisibles. Le rapport les nomme (`vault`) ; si Turnstile est activé,
  l'administration refuse toute connexion, et `restore` donne la commande qui
  le désactive. La connexion qui refuse reste telle quelle : c'est la porte de
  sécurité qui l'exige ;
- **`destroy` relaie le refus de R2**, avec son code, et non plus la ligne par
  laquelle wrangler annonce la suppression (passage réel de l'étape 7).

Runbooks (`docs/operations/`) : une commande `npx wrangler` nomme son compte
(`CLOUDFLARE_ACCOUNT_ID`) ; le retour arrière ramène aussi les secrets de la
version visée ; la rotation de `SECRETS_KEK` désactive Turnstile d'abord ; la
restauration vers un environnement neuf ou un autre compte, et les effacements
RGPD à rejouer après elle ; le mot de passe de staging à remplacer aussi dans
`MINSHOP_ADMIN_PASSWORD`.

## Migrations

- aucune.

## À faire dans la boutique

- rien. Un rapport de `deploy` antérieur à cette version ne dit pas la version
  précédente : pour un retour arrière, prendre l'avant-dernier déploiement de
  `npx wrangler deployments list` (runbook « Worker en erreur », §2).

## Compatibilité

Le manifeste ne change pas : un manifeste v0.3.11 reste valide tel quel, et
`shopctl core upgrade` met `coreVersion` à `0.3.12` tout seul.

Aucune migration, rien ne change dans le Worker : un rollback applicatif vers
`v0.3.11` reste possible sans intervention sur la base.
