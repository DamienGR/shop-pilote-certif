# Socle v0.3.19

<!-- Ce que cette version demande à une boutique qui la prend. Lu par
     `shopctl core upgrade` et repris dans la pull request de mise à niveau. -->

Cette version corrige quatre défauts que le passage réel de l'étape 9 de la
certification a laissés ouverts (jalon 10, `docs/certification/plan.md`). Un
seul se voit dans une boutique : le nom que propose l'assistant d'installation.
Les autres touchent le nocturne et les suites de tests.

## Ce qui change

- **Le nom de la boutique vient du manifeste.** `wrangler.template.jsonc`
  écrivait `STORE_NAME: "Ma boutique"` en dur, et `client.displayName` n'y
  arrivait jamais : l'assistant de la première production du pilote a proposé
  « Ma boutique ». Le rendu du manifeste (`provision`, `deploy`,
  `prepare-client`) y écrit désormais `client.displayName`, échappé pour JSON.
  C'est la valeur par défaut tant que l'assistant ou Réglages n'en enregistrent
  pas une. Les rendus sans manifeste (contrôles de la CI, clone propre,
  `provision-cf.sh`) écrivent toujours « Ma boutique ».
- **Le nocturne nomme ses jobs sans expression** : `Staging`,
  `Production backup`, `Production error rate and quotas`. GitHub n'évalue le
  nom d'un job que s'il tourne, et le job de staging sauté s'affichait
  `Staging (${{ needs.detect.outputs.shop }})`.
- **`actions/upload-artifact` passe en `v7`** dans `nightly.yml`,
  `deploy.yml` et `verify.yml`. La `v4` tournait sur Node 20, que GitHub force
  sur Node 24 avec un avertissement à chaque run. Les artefacts gardent leurs
  noms et leur contenu, et `gh run download` les lit comme avant.
- **Les suites ne lancent plus de maintenance git.** Depuis git 2.47, un commit
  la lance en arrière-plan, et le verrou qu'elle pose dans `.git/objects` a
  fait échouer une copie de dépôt de test sur la CI (`ENOENT`).
  `test/helpers/core-repository.mjs` la coupe pour tout git qu'une suite lance.
- **Les scripts d'intégration arrêtent tout le serveur.** `npx` ne transmet pas
  le signal reçu. `storefront-baselines.sh` et `d1-integration.sh` laissaient
  donc `wrangler dev` et son `workerd` tourner, qui gardaient le port pour le
  passage suivant. Le serveur a maintenant son propre groupe de processus, que
  le nettoyage arrête en entier.
- Le test de frontière de la vitrine a un budget de 30 s au lieu de 5 :
  il parcourt deux fois tous les thèmes.

De nouvelles portes : `test/scripts/workflows.test.mjs` (aucun nom de job tiré
d'un autre job, chaque action sur une version qui tourne sur Node 24),
`test/scripts/git-env.test.mjs`, `test/scripts/integration-scripts.test.mjs`,
et le test des sites de rendu du gabarit, qui couvre maintenant les cinq
endroits où `sed` le remplit.

## Migrations

- aucune.

## À faire dans la boutique

- **rien pour une boutique installée** : le nom enregistré par l'assistant ou
  dans Réglages prime sur `STORE_NAME`, et ne change pas ;
- **une boutique pas encore installée** verra son `client.displayName` proposé
  par l'assistant : le vérifier dans le manifeste avant la mise en ligne ;
- **une règle ou un script qui attend l'ancien nom d'un job du nocturne**, par
  exemple `Staging (<boutique>)`, doit prendre le nouveau.

## Compatibilité

Le manifeste ne change pas : un manifeste v0.3.18 reste valide tel quel, et
`shopctl core upgrade` met `coreVersion` à `0.3.19` tout seul.

Aucune migration : un rollback applicatif vers `v0.3.18` reste possible sans
intervention sur la base.
