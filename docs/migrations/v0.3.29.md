# Socle v0.3.29

<!-- Ce que cette version demande à une boutique qui la prend. Lu par
     `shopctl core upgrade` et repris dans la pull request de mise à niveau. -->

Cette version raccourcit la certification d'une boutique après le pilote : la
campagne a certifié le socle, et une boutique n'en rejoue plus que ce qui lui
est propre ([parcours court](../certification/par-boutique.md)). La preview
sur le compte de l'agence devient facultative (ADR 0015, amendé le
2026-10-27). Travail d'après le pilote, hors des jalons 0 à 10.

## Ce qui change

- **`shopctl certify --env production`.** Une commande, en lecture seule sur
  tous les comptes, qui juge le socle de la boutique (un tag publié au moins
  égal à `v0.3.28`, aucune divergence non déclarée), son arbre, son compte
  Cloudflare, ses réglages de production (lus masqués), sa vitrine publique
  (pages légales, portes de sécurité et navigateur distantes, Lighthouse par
  PageSpeed Insights), son dépôt GitHub et les attestations de sa recette.
  `--write` écrit le rapport dans `client/certification/<date>/` et pose le
  modèle de `client/certification/attestations.yaml`. Code 6 tant qu'elle
  n'est pas certifiable.
- **La vitrine demande aux moteurs de ne pas l'indexer tant qu'aucun moyen de
  paiement réel n'est ouvert** (`<meta name="robots" content="noindex">`).
  Une production construite en public n'est plus trouvée à moitié saisie. Le
  premier moyen réel la rouvre sans déploiement ; un catalogue au panier coupé
  reste indexé.
- **Le nocturne n'interroge plus qu'un staging déclaré** : `stagingDomain` dans
  le manifeste, ou la variable **de dépôt** `STAGING_URL`. Une boutique sans
  preview reçoit un avis « Aucun staging déclaré » au lieu d'un job rouge.

## Migrations

Aucune.

## À faire dans la boutique

- si le staging de la boutique est sur `workers.dev` (pas de `stagingDomain`)
  et que `STAGING_URL` est une variable de l'environnement GitHub `staging`,
  la reposer au niveau du dépôt : `gh variable set STAGING_URL --body
  <origine>`. Sinon le nocturne ne voit plus ce staging, et le dit par un
  avis ;
- une boutique encore fermée (aucune clé Stripe) porte désormais `noindex` :
  c'est voulu. `pilote-certif`, fermée par décision, en fait partie ;
- pour certifier : [docs/certification/par-boutique.md](../certification/par-boutique.md).

## Compatibilité

Le manifeste ne change pas : un manifeste v0.3.28 reste valide tel quel, et
`shopctl core upgrade` met `coreVersion` à `0.3.29` tout seul.

Aucune migration : un rollback applicatif vers `v0.3.28` reste possible sans
intervention sur la base.
