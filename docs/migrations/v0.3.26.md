# Socle v0.3.26

<!-- Ce que cette version demande à une boutique qui la prend. Lu par
     `shopctl core upgrade` et repris dans la pull request de mise à niveau. -->

Cette version prend les montées mineures de Dependabot (Astro 7.4) et relève
le plancher de Node qu'elles imposent. Elle ne touche ni le schéma ni le
manifeste.

## Ce qui change

- **Node 22.23.4 au moins.** Astro 7.4 tire `@astrojs/prism` 4.1.1, qui exige
  Node 22.23.4, la version de sécurité du 2026-10-20. `engines` (racine et
  `mcp/`) passe de `>=22.12.0 <23` à `>=22.23.4 <23` : avec `engine-strict`,
  `npm ci` refusait l'installation sur un Node plus ancien, et le message
  nommait une dépendance au lieu du socle. `npm run check:toolchain` dit
  maintenant `nvm install`, pas `nvm use` : avec un `.nvmrc` qui ne nomme que
  la majeure, `nvm use` garde le 22.x déjà installé, celui qu'il vient de
  refuser.
- **La CI prend le dernier Node 22.** `setup-node` résolvait la majeure de
  `.nvmrc` vers la version en cache sur l'image du runner, qui suit les
  sorties de Node avec plusieurs semaines de retard : le 2026-10-25, elle
  avait encore 22.23.3, et la pull request Dependabot #112 était rouge sur
  toutes ses installations. Chaque `setup-node` qui lit `.nvmrc` porte
  désormais `check-latest: true` ; `test/scripts/workflows.test.mjs` refuse
  celui qui l'oublierait.
- **Les montées de Dependabot** (#112) : `astro` 7.4.2, `@astrojs/cloudflare`
  14.4.2, `@astrojs/check` 0.9.12, `wrangler` 4.151.3,
  `@cloudflare/workers-types` 5.20261022.1, `@playwright/test` 1.64.1 et
  `@axe-core/playwright` 4.14.0.

## Migrations

- aucune.

## À faire dans la boutique

- sur le poste de l'opérateur, `nvm install 22` avant `npm ci` : il installe
  la dernière 22.x et la sélectionne. `npm run check:toolchain` le dit si ce
  n'est pas fait ;
- rien dans les workflows : ce sont des fichiers du socle, la montée les
  apporte.

## Compatibilité

Le manifeste ne change pas : un manifeste v0.3.25 reste valide tel quel, et
`shopctl core upgrade` met `coreVersion` à `0.3.26` tout seul.

Aucune migration : un rollback applicatif vers `v0.3.25` reste possible sans
intervention sur la base.
