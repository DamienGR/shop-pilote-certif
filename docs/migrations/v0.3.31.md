# Socle v0.3.31

<!-- Ce que cette version demande à une boutique qui la prend. Lu par
     `shopctl core upgrade` et repris dans la pull request de mise à niveau. -->

Cette version prend les trois montées de Dependabot restées ouvertes (#89,
#90, #118). Elle ne touche ni le code, ni le schéma, ni le manifeste. Travail
d'après le pilote, hors des jalons 0 à 10.

## Ce qui change

- **`stripe` 23.0.1** (était 22.6.1). Le SDK épingle désormais la version
  d'API `2026-09-30.endive` : c'est elle que le Worker envoie à Stripe en
  créant une session, en relisant un tarif de livraison ou en remboursant. Sa
  rupture côté Checkout est le retrait de `payment_method_types` à la création
  d'une session, que le socle ne passe pas (les moyens de paiement viennent du
  tableau de bord Stripe). La vérification des webhooks reste
  `constructEventAsync`, avec la même tolérance de cinq minutes. La version
  d'API d'un endpoint de webhook, elle, est celle choisie à sa création dans le
  tableau de bord : la montée ne la change pas.
- **`vitest` 5.0.5** (était 4.1.12), outil de développement seulement : la
  configuration ne change pas.
- **`wrangler` 4.154.0** (était 4.151.3), avec workerd 1.20261023.1 ; npm
  monte `@cloudflare/workers-types` en 5.20261028.1 pour suivre.

## Migrations

- aucune.

## À faire dans la boutique

- rien. Le premier paiement Stripe après le déploiement se vérifie comme
  d'habitude (commande payée, e-mail reçu) ; `npm run test:stripe:remote`
  rejoue l'aller-retour du webhook sur un environnement en mode test.

## Compatibilité

Le manifeste ne change pas : un manifeste v0.3.30 reste valide tel quel, et
`shopctl core upgrade` met `coreVersion` à `0.3.31` tout seul.

Aucune migration : un rollback applicatif vers `v0.3.30` reste possible sans
intervention sur la base.
